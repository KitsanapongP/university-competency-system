# มาตรฐาน UI สำหรับหน้าจัดการของ Officer และ Admin

เอกสารนี้กำหนดกติกากลางสำหรับหน้าปฏิบัติงานที่ใช้จัดการข้อมูลหลักสูตร ผู้เรียน
กิจกรรม สมรรถนะ แบบแผนการประเมิน และวิชาเสรี โดยยึดรูปแบบของหน้า Curriculum
Management และ Template Management เป็นภาษาภาพหลัก

## เป้าหมาย

- ให้หน้าจัดการทุกหน้ามีโครงสร้าง ระยะห่าง และลำดับข้อมูลที่คาดเดาได้
- ให้ใช้ฟอนต์ สี เส้นขอบ และความโค้งจากชุดค่าเดียวกันทั้ง Light และ Dark theme
- ให้ข้อความที่หน้าเว็บสร้างขึ้นรองรับภาษาไทยและอังกฤษผ่านตัวช่วยแปลของฟีเจอร์
- ให้หน้าใหม่เพิ่มได้โดยใช้ส่วนประกอบและตัวแปรสีเดิม แทนการสร้างค่าซ้ำ

## โครงสร้างหน้า

หน้าจัดการในขอบเขตควรมีคลาสมาตรฐานต่อไปนี้ร่วมกับคลาสเฉพาะของฟีเจอร์:

- `ui-page` เป็นรากของหน้า และ `ui-page__header` เป็นส่วนหัวของหน้า
- `ui-page__heading`, `ui-page__title`, `ui-page__subtitle` ใช้จัดลำดับหัวข้อ
- `ui-page__actions` ใช้จัดกลุ่มคำสั่งหลักของหน้า
- `ui-panel` ใช้กับแผงข้อมูลที่มีกรอบ และ `ui-panel__heading` หรือ
  `ui-panel__toolbar` ใช้กับส่วนหัวของแผง
- `ui-filter-grid` ใช้จัดตัวกรอง และ `ui-field` ใช้จับคู่ป้ายกับช่องกรอก
- `ui-table-wrap` ใช้จำกัดการเลื่อนของตาราง และ `ui-table` ใช้รูปแบบตารางกลาง

คลาส `officer-page` และ `officer-page__*` ยังคงเป็นชื่อเข้ากันได้กับ CSS เดิม
ระหว่างการย้ายหน้า แต่ตัวแปรและส่วนประกอบใหม่ควรใช้ชื่อ `ui-*` เป็นหลัก

## ตัวอักษรและระยะห่าง

- ใช้ `Sarabun` เป็นฟอนต์หลักของหน้าจัดการ พร้อมฟอนต์สำรองแบบ sans-serif
- พื้นที่เนื้อหาหลักใช้ระยะขอบด้านข้างกว้างบนจอใหญ่ และลดลงตามจุดตัดหน้าจอ
- ใช้ระยะห่างตามชุดค่าเดียวกัน: ประมาณ `1.5rem` ถึง `2rem` ระหว่างส่วนหลัก,
  `1rem` ภายในแผง และ `0.5rem` ระหว่างป้ายกับช่องกรอก
- แผง ช่องกรอก และปุ่มใช้ความโค้งจาก `--ui-radius-*` โดยไม่เกินมาตรฐานงานจัดการ
- ชื่อหน้าต้องเด่นกว่าคำอธิบาย และชื่อแผงต้องเล็กกว่าชื่อหน้า

## สีและธีม

`app/(officer)/UiTokens.css` เป็นแหล่งหลักของ semantic tokens เช่น
`--ui-page-bg`, `--ui-surface`, `--ui-text`, `--ui-border`, `--ui-primary`,
`--ui-success`, `--ui-warning` และ `--ui-danger` โดยกำหนดค่าทั้ง Light และ Dark
theme ในที่เดียว

`UiPrimitives.css` ใช้ tokens เหล่านี้สร้างรูปแบบกลางของหน้า แผง ตัวกรอง ปุ่ม
สถานะ และตาราง ส่วน `OfficerDesign.css` เก็บชื่อ `--officer-*` เป็น compatibility
alias สำหรับ CSS เดิมเท่านั้น หน้า Curriculum ใช้ `--course-*` และหน้า Template
ใช้ `--tm-*` ซึ่งเชื่อมกลับมายัง `--ui-*` แล้ว ไม่ควรเพิ่มค่าสีตายตัวชุดใหม่

สีเฉพาะสถานะใช้ token ที่มีความหมายตรงกับสถานะ และต้องตรวจความเปรียบต่างในทั้ง
สองธีม ควรหลีกเลี่ยงการใช้สีจากชื่อหน้าหรือชื่อคอมโพเนนต์เป็นตัวกำหนดความหมาย

## ภาษาและข้อความ

ข้อความที่หน้าเว็บสร้างขึ้นต้องมีภาษาไทยและอังกฤษ โดยใช้ `officerText` จาก
`app/(officer)/officer-labels.js` หรือ helper ของฟีเจอร์เมื่อมีคำเฉพาะโดเมน
ไม่ควรแสดงรหัสภายในแทนชื่อที่ผู้ใช้ต้องอ่าน และไม่ควรปล่อยคำว่า `Draft`,
`Session` หรือข้อความจากฐานข้อมูลปะปนในประโยคภาษาไทยโดยไม่มีคำอธิบาย

ข้อความสถานะควรบอกสิ่งที่เกิดขึ้นหรือสิ่งที่ผู้ใช้ทำต่อได้ เช่น “ยังไม่มีข้อมูล”
หรือ “ไม่พบข้อมูลตามเงื่อนไขที่เลือก” แทนการใช้เครื่องหมาย `-` เพียงอย่างเดียว

## ขอบเขต

มาตรฐานนี้ครอบคลุมหน้าปฏิบัติงานภายใต้ `app/(officer)` ได้แก่ Curriculum,
Template, วิชาเสรี, ผู้เรียน, กิจกรรม, สาขา, สมรรถนะ, การมอบหมายแบบแผนการประเมิน
รวมถึงหน้ารอบกิจกรรมและหน้าปฏิบัติงานเช็กชื่อหรือคะแนน

เมื่อเพิ่มหน้าจัดการใหม่ ให้เริ่มจาก `ui-page` และใช้ tokens จาก `UiTokens.css`
ก่อนสร้าง CSS เฉพาะหน้า หากจำเป็นต้องรองรับคลาสเดิม ให้เพิ่ม compatibility alias
ในไฟล์ธีมที่เกี่ยวข้องและวางแผนลบ alias เมื่อทุกหน้าถูกย้ายเสร็จ

## การตรวจสอบ

รัน `npm.cmd run test:officer-ui` เพื่อตรวจว่าหน้าจัดการมีรากหน้า ส่วนหัว และ
ส่วนประกอบมาตรฐาน รวมถึงตรวจว่าชุด semantic tokens และส่วนประกอบกลางยังอยู่
จากนั้นรัน ESLint, `npm.cmd run build` และ `git diff --check` ก่อนส่งงาน
