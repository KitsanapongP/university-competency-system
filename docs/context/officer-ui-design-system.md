# มาตรฐาน UI สำหรับ Role Officer

เอกสารนี้กำหนดกติกากลางสำหรับหน้าจัดการข้อมูลที่เจ้าหน้าที่ใช้ทำงานซ้ำ ๆ เช่น
จัดการผู้เรียน กิจกรรม สมรรถนะ สาขา แบบแผนการประเมิน และวิชาเสรี

## เป้าหมาย

- ให้หน้าจัดการทุกหน้ามีโครงสร้าง ระยะห่าง และการจัดลำดับข้อมูลที่คาดเดาได้
- ให้ผู้ใช้สลับภาษาไทยและอังกฤษได้ครบในข้อความที่หน้าเว็บสร้างขึ้น
- ให้หน้าจออ่านได้ทั้ง Light theme และ Dark theme โดยไม่ผูกสีไว้กับหน้าใดหน้าหนึ่ง
- ให้เพิ่มหน้าใหม่ได้โดยใช้ส่วนประกอบและตัวแปรสีเดิม แทนการสร้างค่าซ้ำ

## โครงสร้างหน้า

หน้าจัดการที่อยู่ในขอบเขตต้องมีรากหน้าที่ใช้ `officer-page` และส่วนหัวที่ใช้
`officer-page__header` โดยจัดส่วนสำคัญตามลำดับนี้:

1. ชื่อหน้า คำอธิบาย และปุ่มคำสั่งหลัก
2. ตัวกรองหรือแถบเครื่องมือ
3. แผงข้อมูล ตาราง หรือรายการหลัก
4. สถานะกำลังโหลด ข้อมูลว่าง และข้อผิดพลาดที่อ่านเข้าใจได้

ใช้ `officer-panel`, `officer-filter-grid`, `officer-table-wrap` และ
`officer-table` เมื่อหน้าต้องการรูปแบบมาตรฐานของแผง ตัวกรอง หรือ ตาราง

## ตัวอักษรและระยะห่าง

- ใช้ฟอนต์ `Prompt` เป็นฟอนต์หลักของหน้า Role Officer
- พื้นที่เนื้อหาหลักใช้ระยะขอบด้านข้างแบบกว้างบนจอใหญ่ และลดลงบนจอแคบ
- ใช้ระยะห่างตามชุดค่าเดียวกัน: ประมาณ `2rem` ระหว่างส่วนหลัก,
  `1rem` ภายในแผง และ `0.5rem` ระหว่างป้ายกับช่องกรอก
- ใช้ความโค้งไม่เกิน `8px` สำหรับแผง ช่องกรอก และปุ่มตามมาตรฐานงานจัดการ
- ชื่อหน้าต้องเด่นกว่าคำอธิบาย และชื่อแผงต้องเล็กกว่าชื่อหน้า

## สีและธีม

ใช้ตัวแปรจาก `OfficerDesign.css` เป็นหลัก เช่น `--officer-bg`,
`--officer-surface`, `--officer-text`, `--officer-border` และ
`--officer-primary` หลีกเลี่ยงการใส่ค่าสีตายตัวใน CSS ของหน้า เว้นแต่เป็นสี
เฉพาะสถานะที่มีตัวแปรรองรับแล้ว

ปุ่มคำสั่งหลักใช้ `course-btn--primary` ปุ่มคำสั่งรองใช้
`course-btn--ghost` และปุ่มที่มีความเสี่ยงใช้รูปแบบ `danger` ที่มีอยู่
ตารางต้องเลื่อนในพื้นที่ของตารางเมื่อเนื้อหากว้าง เพื่อไม่ให้ทั้งหน้าถูกยืด

## ภาษาและข้อความ

ข้อความที่หน้าเว็บสร้างขึ้นต้องมีภาษาไทยและอังกฤษ โดยใช้ `officerText` จาก
`app/(officer)/officer-labels.js` หรือ helper ของฟีเจอร์เมื่อมีคำเฉพาะโดเมน
ไม่ควรแสดงรหัสภายในแทนชื่อที่ผู้ใช้ต้องอ่าน และไม่ควรปล่อยคำว่า `Draft`,
`Session` หรือข้อความจากฐานข้อมูลปะปนในประโยคภาษาไทยโดยไม่มีคำอธิบาย

ข้อความสถานะควรบอกสิ่งที่เกิดขึ้นหรือสิ่งที่ผู้ใช้ทำต่อได้ เช่น “ยังไม่มีข้อมูล”
หรือ “ไม่พบข้อมูลตามเงื่อนไขที่เลือก” แทนการใช้เครื่องหมาย `-` เพียงอย่างเดียว

## ขอบเขต

มาตรฐานนี้ถูกนำมาใช้กับหน้าปฏิบัติงานของ Role Officer ในรอบแรก ได้แก่ วิชาเสรี
ผู้เรียน กิจกรรม สาขา สมรรถนะ และการมอบหมายแบบแผนการประเมิน รวมถึงหน้าจัดการ
รอบกิจกรรมและหน้าปฏิบัติงานเช็กชื่อ/คะแนน

หน้า Curriculum Management และตัวแก้ไข Template ซึ่งมีรูปแบบการทำงานเฉพาะและ
มี CSS เดิมขนาดใหญ่ยังไม่ถูกย้ายในรอบนี้ การแก้หน้าเหล่านั้นควรทำเป็นงานแยกและ
ต้องตรวจผลกระทบกับผู้ใช้เดิมก่อน
