# Verified Learner Assessment Observations

## Decision

Version 1.0 uses Go-verified observations rather than independent model judgments of ability. RAG, vector storage, career recommendations, new grade thresholds, and multi-call generation are outside this change. No database migration is required; report content and source snapshots use existing JSON columns.

The authoritative pipeline is:

`existing scoped evidence -> deterministic observations -> constrained bilingual narrative -> validation -> latest report per semester`

## Observation Rules

- Only the original readiness evaluator's `met` and `not_met` outcomes become requirement-attainment or development findings. `missing_grade`, unavailable criteria, and unavailable scores are not personal limitations.
- Readiness status, counts, titles, numeric facts, grades, thresholds, and citations are filled by Go, not generated by the model. The readiness explanation tells learners to consult the original per-criterion results and never grants approval.
- Academic grades, competency contributions, and participation records without an explicit comparator are neutral observations. B+ is not a weakness simply because it is below A.
- Competency totals remain accumulated contributions, not scores out of 100. Activity participation does not establish expertise or personality.
- Existing temporal boundaries and best-grade rules remain in the source builders/evaluators. Course evidence precedes the selected semester; activities use the latest available evidence. Historical course observations are records, not a replacement for the best-attempt calculations.

## Provider and Stored Contracts

Ollama receives verified facts with `observation_id` and `kind`. Arbitrary official names, descriptions, learner identity, raw evidence arrays, and duplicate citation lists are not sent in the prompt. Names and original evidence remain in the stored snapshot for the UI.

The model returns required `strengths`, `limitations`, and `observations` arrays, at most three items per array. Each item contains `observation_id` and bilingual `explanation`; limitations additionally require bilingual `development_advice`. Empty arrays are valid. Each language field is limited to 240 characters.

JSON Schema binds IDs to their permitted sections using `enum`. The backend rejects unknown/duplicate/misplaced IDs, unknown fields, missing sections/languages, unsolicited advice, overlong text, and obvious numeric/grade assertions not present in the selected observation. It then supplies the stored `title`, `reason`, and `evidence_refs` from Go and retains the validated narrative separately as `explanation`.

Numeric/grade checking is conservative and lexical. It can reject innocuous isolated uppercase grade letters, and cannot establish semantic equivalence, correct numeric roles, implicit judgments, written-out numbers, or translations. It is not a semantic correctness guarantee. Do not weaken validation or silently rewrite/remove a bad citation to publish a result.

## Completion and Failure Handling

- Ollama `done_reason=length` produces non-retryable `provider_output_truncated`, even if `done=true` or the response appears syntactically valid.
- Unfinished responses are rejected. For compatibility, a missing `done_reason` is still accepted only with `done=true` and nonempty output; current Ollama reports a reason.
- Malformed JSON is `malformed_output`; structurally valid but unsupported output is `invalid_output`.
- Operational usage logs contain only a bounded completion reason and nonnegative `prompt_eval_count`/`eval_count`. No prompt, response, names, grades, evidence, or learner identifiers are logged.
- Invalid output is never persisted or automatically repaired. Existing cooldowns, bounded transport retries, leases, source-supersession checks, and stale-report hiding remain unchanged.

## Versions and Rollout

- Pipeline: `learner-assessment-v1.0.2`
- Prompt: `learner-assessment-prompt-v1.0.3`
- Output schema: `learner-assessment-output-v1.0.2`

Version changes invalidate old report freshness. Deploy matching API/worker binaries and configuration together; stop the old worker before replacing it. Old pipeline jobs are rejected rather than processed with the new contract. Reports are rebuilt lazily through the existing stale-report flow.

The 6144-context/2048-output profile is experimental. The automated gate passed 12 synthetic generations, but semantic review found remaining English wording errors. Do not promote it to a production default or declare the model production-ready until semantic review and combined-workload resource limits pass. Defaults remain 4096/1024/128 with thinking off.
